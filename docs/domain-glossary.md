# 领域术语表（节点 0.2）

本文只冻结节点 0.2 的术语。不启动 0.3。不写实现、SQL、API 或数据库模式。  
术语必须与节点 0.1（`docs/mvp-scope.md`）一致，不得与之冲突。

## 0. 硬约束（验收必读）

与 0.1 对齐，下列为 MVP 正常行为；相反项不是正常行为：

- 一个小说项目、一名用户（创作者兼主编）、仅中文、一个写作模型供应商、生成单位为场景、必须人类批准。
- 模型、实现 bot、验收 bot 均不得自动修改 Canon。只有人类主编可以批准。
- Canon 高于散文。散文只可产生候选变更。
- **场景草稿（Scene Draft）与 Canon 冲突时，Canon 胜。** 冲突草稿不得覆盖、改写或充当 Canon。
- **自动批准不是 MVP 正常行为。** 不得把自动批准写成默认、可选正常路径或「稍后可开」。
- **多项目不是 MVP 正常行为。** 不得把同时存在第二个故事项目写成默认或正常路径。

## 1. 三件套：Canon Fact、Candidate Change、Evidence

三者必须同时理解，缺一不可：

| 成员 | 是什么 | 不是什么 | 能否单独改 Canon |
| --- | --- | --- | --- |
| **Evidence（证据）** | 候选变更的出处依据，通常摘自场景草稿或已写定的 Story Spec 文句 | 不是提案，不是已批准真相 | 否 |
| **Candidate Change（候选变更）** | 从散文抽取的待裁决变更，必须绑定 Evidence | 不是 Canon Fact | 否。不得直接写入 Canon |
| **Canon Fact（Canon 事实）** | 已在 Canon 中生效的一条已批准真相 | 不是未裁决的候选 | 仅当对应候选变更通过校验、且人类主编批准并提交后，才成为或更新 Canon Fact |

关系（可检查）：

1. 场景草稿只产生候选变更，并为其提供 Evidence。
2. 候选变更必须带 Evidence，才能进入 Validate。
3. 未通过校验的候选变更不能进入人类裁决。
4. 通过校验后，只有人类主编批准或拒绝；**不存在自动批准**。
5. 仅「批准 → 提交」才会把该候选变成（或更新）Canon Fact。Evidence 被引用不会使自己变成 Canon。
6. 若场景草稿与已有 Canon / Canon Fact 冲突：**Canon 胜**。冲突文字最多成为带 Evidence 的候选变更，主编可以拒绝；草稿本身不能改 Canon。

## 2. 冻结术语（不多、不漏）

下列 30 条为冻结清单。每条均含：中文名、英文代码名、一句话定义、生命周期/状态、与最容易混淆概念的差异、一个小说生成例子。  
不在本表中的词（如主编、Validate、生成）沿用 0.1，不在本节点另立新术语。

### Story Project / 故事项目

- **中文名**：故事项目
- **英文代码名**：Story Project
- **一句话定义**：本 MVP 中唯一的一部小说工作容器，承载该小说的 Story Spec、Canon 与场景生成。
- **生命周期/状态**：创建 → 唯一存活（进行中）。不得同时存在第二个故事项目。
- **与最容易混淆概念的差异**：不是 Story Spec。项目是容器；规格是约束文本。
- **一个小说生成例子**：主编只开《青石夜祠》这一个故事项目，不为第二部小说开设项目。

### Story Spec / 故事规格

- **中文名**：故事规格
- **英文代码名**：Story Spec
- **一句话定义**：人类主编写定的故事规格，约束这部小说要写什么、不能写什么。
- **生命周期/状态**：草稿 → 主编写定 → 生效约束。修订只能由主编改写，不因散文自动改写。
- **与最容易混淆概念的差异**：不是 Canon。规格是编辑约束（要写/不能写）；Canon 是已批准的故事内真相。
- **一个小说生成例子**：规格写明「只写林晚在青石镇的七日、禁止第二主角视角」，生成不得另开旁观者全书视角。

### Canon / 已批准真相

- **中文名**：已批准真相
- **英文代码名**：Canon
- **一句话定义**：经人类主编批准后提交的故事真相；效力高于任何散文。
- **生命周期/状态**：空或初值 → 仅在主编批准后提交增量 → 当前已批准真相。模型、实现 bot、验收 bot 均不得自动修改。
- **与最容易混淆概念的差异**：不是 Scene Draft。草稿是散文；Canon 是已批准真相。草稿与 Canon 冲突时，Canon 胜。
- **一个小说生成例子**：主编已批准「残玉只能由林晚触活」。后文草稿写成路人也能触活，该句不能改 Canon。

### Canon Fact / Canon 事实

- **中文名**：Canon 事实
- **英文代码名**：Canon Fact
- **一句话定义**：Canon 中的一条已批准、可独立核验的真相陈述。
- **生命周期/状态**：尚未进入 Canon → 对应候选变更被主编批准并提交后成为已提交 → 若被新的批准提交替换则进入被覆盖。未批准前不是 Canon 事实。
- **与最容易混淆概念的差异**：不是 Candidate Change。Canon 事实已在 Canon 内生效；候选变更尚未生效。
- **一个小说生成例子**：「林晚左腕有烧痕」经主编批准并提交后，才是一条 Canon 事实。

### Candidate Change / 候选变更

- **中文名**：候选变更
- **英文代码名**：Candidate Change
- **一句话定义**：从生成散文中抽取、不得直接写入 Canon、须经校验与人类主编裁决的待裁决变更。
- **生命周期/状态**：已抽取 → 校验中 → 未通过（不得进入批准）/ 待主编裁决 → 批准并提交 / 拒绝。不存在自动批准。
- **与最容易混淆概念的差异**：不是 Canon Fact，也不是 Evidence。候选是提案；事实是已批准结果；证据是依据。
- **一个小说生成例子**：草稿写「林晚把残玉按进祠门」，抽出「残玉可开祠门」为候选变更，等待主编批准或拒绝。

### Evidence / 证据

- **中文名**：证据
- **英文代码名**：Evidence
- **一句话定义**：支撑一条候选变更的出处依据（通常来自场景草稿或已写定的规格文句）；证据本身不是 Canon。
- **生命周期/状态**：随抽取产生并绑定某条候选变更 → 随该候选被批准或拒绝而归档。被引用不会使证据自动成为 Canon。
- **与最容易混淆概念的差异**：不是 Candidate Change。证据说明「根据哪段文字提出变更」；候选变更才是要不要写入 Canon 的提案。
- **一个小说生成例子**：候选「残玉可开祠门」的证据是草稿句「她把残玉按进缺口，门轴轻响」。

### Outline / 大纲

- **中文名**：大纲
- **英文代码名**：Outline
- **一句话定义**：这部小说的结构骨架，用来排列卷或弧、章与场景的先后；大纲不是生成单位。
- **生命周期/状态**：拟定 → 主编确认可用 → 可修订。大纲修订不自动改 Canon。
- **与最容易混淆概念的差异**：不是 Scene Plan。大纲管全书结构；场景计划只管一个场景的节拍。
- **一个小说生成例子**：大纲规定第一日「得玉」、第二日「试门」，但不直接生成这两日的正文。

### Arc / 卷或弧

- **中文名**：卷或弧
- **英文代码名**：Arc
- **一句话定义**：大纲中的一段情节弧或一卷，聚合若干章；不是生成单位。
- **生命周期/状态**：规划中 → 进行中 → 收束。收束不等于 Canon 自动更新。
- **与最容易混淆概念的差异**：不是 Chapter。卷或弧包含章；一章不是一条弧。
- **一个小说生成例子**：「七日寻祠」是一条弧，下面有「得玉」「试门」等章，仍按场景逐场生成。

### Chapter / 章

- **中文名**：章
- **英文代码名**：Chapter
- **一句话定义**：叙事上的一章，包含一个或多个场景；本 MVP 不以章为生成单位。
- **生命周期/状态**：规划 → 其下场景逐个生成 → 章内场景齐备。不得以「生成一整章」作为本 MVP 正常入口。
- **与最容易混淆概念的差异**：不是 Scene。章是容器；场景才是生成单位。
- **一个小说生成例子**：第一章「青石遇玉」含「河边拾玉」「回家藏玉」两场，分别出两张场景卡。

### Scene / 场景

- **中文名**：场景
- **英文代码名**：Scene
- **一句话定义**：本 MVP 的唯一生成单位：一次只生成一个场景的叙事片段。
- **生命周期/状态**：指定待写 → 持有场景卡 → 已生成草稿 → 抽取/校验/裁决后可进入下一场景。不得一次生成整章或全书。
- **与最容易混淆概念的差异**：不是 Chapter，也不是 Scene Card。场景是叙事单位；场景卡是该次生成的任务卡。
- **一个小说生成例子**：只生成「林晚在河滩捡到残玉」这一场，不一次写出整章。

### Scene Card / 场景卡

- **中文名**：场景卡
- **英文代码名**：Scene Card
- **一句话定义**：一次场景生成的任务卡，规定该场景的生成边界。
- **生命周期/状态**：为主编指定的场景编写 → 用于生成该场散文 → 用后归档。不因生成结果自动改 Canon。
- **与最容易混淆概念的差异**：不是 Scene Plan。场景卡规定边界（能写到哪、不能写什么）；场景计划描述节拍意图。
- **一个小说生成例子**：卡片写「地点=河滩，在场=林晚，禁止写出残玉来历」，模型只能在此边界内写捡玉。

### Scene Plan / 场景计划

- **中文名**：场景计划
- **英文代码名**：Scene Plan
- **一句话定义**：单个场景的节拍与意图安排，说明该场要发生什么；本身不是已批准真相。
- **生命周期/状态**：拟定 → 供写卡或生成参照 → 可废弃或改写。计划与 Canon 冲突时，Canon 胜。
- **与最容易混淆概念的差异**：不是 Scene Draft。计划是意图；草稿是生成出的散文。
- **一个小说生成例子**：计划写「先冷、后见光、再拾玉」，只约束这一场节奏，不直接写入 Canon。

### Scene Draft / 场景草稿

- **中文名**：场景草稿
- **英文代码名**：Scene Draft
- **一句话定义**：按场景卡生成的该场景散文；只可从中抽取候选变更，不得直接改 Canon。
- **生命周期/状态**：未生成 → 已生成 → 已抽取候选变更 → 可出修订版本。草稿与 Canon 冲突时，Canon 胜；冲突段落不能覆盖 Canon。
- **与最容易混淆概念的差异**：不是 Canon。草稿是散文与候选来源；Canon 是已批准真相。
- **一个小说生成例子**：草稿写「残玉在路人手中也亮了」。该句与 Canon「只有林晚能触活」冲突，Canon 胜，该句不得写入 Canon。

### Entity / 实体

- **中文名**：实体
- **英文代码名**：Entity
- **一句话定义**：故事中可被指称的对象总称；角色、物品、地点等都是实体。
- **生命周期/状态**：在规格或草稿中被提及 → 经候选变更与主编批准并提交后，相关陈述才进入 Canon。未批准前不是 Canon。
- **与最容易混淆概念的差异**：不是 Character。实体是总类；角色只是其中一种。
- **一个小说生成例子**：「林晚」「残玉」「青石镇祠堂」都是实体；不能把「实体」窄成只等于角色。

### Character / 角色

- **中文名**：角色
- **英文代码名**：Character
- **一句话定义**：故事中的行动者类实体。本 MVP 只有一名用户，但小说内可有多名角色；用户不是角色。
- **生命周期/状态**：设定提及 → 出场于场景 → 相关事实须经候选变更与主编批准才进入 Canon。
- **与最容易混淆概念的差异**：不是用户或主编。用户是现实中唯一操作者；角色是书中人物。
- **一个小说生成例子**：林晚是角色；主编是用户。不得写成「林晚批准 Canon」。

### Item / 物品

- **中文名**：物品
- **英文代码名**：Item
- **一句话定义**：故事中可被持有、使用或转移的物类实体。
- **生命周期/状态**：被提及 → 在场景中出现或转移 → 其属性须经批准并提交后才成为 Canon 事实。
- **与最容易混淆概念的差异**：不是 Location。物品可被带走；地点是场所。
- **一个小说生成例子**：残玉是物品；林晚把它从河滩带回家，家仍是地点。

### Location / 地点

- **中文名**：地点
- **英文代码名**：Location
- **一句话定义**：故事中的场所类实体，规定场景发生在何处。
- **生命周期/状态**：被提及 → 作为场景卡边界使用 → 其布局或场所规则须经批准并提交后才成为 Canon 事实。
- **与最容易混淆概念的差异**：不是 Scene。地点是场所；场景是在该场所发生的一场叙事。
- **一个小说生成例子**：青石镇河滩是地点；「林晚在河滩捡玉」才是场景。

### World Rule / 世界规则

- **中文名**：世界规则
- **英文代码名**：World Rule
- **一句话定义**：故事世界内生效的法则（自然、制度或超常限制）；批准并提交后成为 Canon 的一部分。
- **生命周期/状态**：由规格或草稿提出 → 成为候选变更 → 主编批准并提交后成为 Canon 事实。未批准的规则对真相无效。
- **与最容易混淆概念的差异**：不是 Story Spec。规格是主编的编辑约束；世界规则是书内法则。
- **一个小说生成例子**：「夜半不得入祠，入则灯灭」若经批准，即世界规则；「本书禁止第二视角」是规格，不是世界规则。

### Event / 事件

- **中文名**：事件
- **英文代码名**：Event
- **一句话定义**：时间线上已发生或拟发生的一件事；只有批准并提交后才成为 Canon 中的已发生事实。
- **生命周期/状态**：计划或草稿叙述 → 候选变更 → 批准并提交后为已发生 Canon 事实 / 拒绝则未进入 Canon。
- **与最容易混淆概念的差异**：不是 Scene。事件是「发生了什么」；场景是「这一场怎么写」。
- **一个小说生成例子**：「林晚于第一日黄昏拾得残玉」是事件；写成河滩对话与动作的那一场是场景。

### Relationship / 关系

- **中文名**：关系
- **英文代码名**：Relationship
- **一句话定义**：两个或多个实体之间的稳定联系（亲缘、敌友、持有、从属等）；批准并提交后才是 Canon。
- **生命周期/状态**：被叙述或设定 → 候选变更 → 批准并提交后生效。草稿里的口误关系不能自动进入 Canon。
- **与最容易混淆概念的差异**：不是 Knowledge Boundary。关系是实体间联系；知情边界是谁知道什么。
- **一个小说生成例子**：「林晚持有残玉」是持有关系；「镇长知道残玉来历」是知情，不是同一概念。

### Secret / 秘密

- **中文名**：秘密
- **英文代码名**：Secret
- **一句话定义**：对部分角色隐瞒、但 Canon 可以已经收录的真相内容。
- **生命周期/状态**：埋设（可在规格中写定，或经批准进入 Canon）→ 仍对指定角色保密 → 揭晓须再经候选变更与主编批准。
- **与最容易混淆概念的差异**：不是 Foreshadowing。秘密是被隐瞒的真相；伏笔是给后文的提示，不等于秘密的全部内容。
- **一个小说生成例子**：Canon 已有「残玉是祠门钥匙」，林晚尚不知——这是秘密，不是伏笔本身。

### Knowledge Boundary / 知情边界

- **中文名**：知情边界
- **英文代码名**：Knowledge Boundary
- **一句话定义**：规定某个角色此时知道什么、不知道什么的边界，用于防止穿帮。
- **生命周期/状态**：随已批准的 Canon 事实与秘密设定 → 写入场景卡约束生成 → 草稿越界则记违规。不得靠自动批准抹掉越界。
- **与最容易混淆概念的差异**：不是 Secret。秘密是被藏的内容；知情边界是「谁此刻能知道哪些内容」。
- **一个小说生成例子**：场景卡写「林晚不知残玉能开门」；草稿若写她未试先说「这是钥匙」，即越过知情边界。

### Timeline / 时间线

- **中文名**：时间线
- **英文代码名**：Timeline
- **一句话定义**：已批准事件的先后次序；散文中的时间表述不得自行改写该次序。
- **生命周期/状态**：随已批准事件增长 → 当前次序有效。草稿时间矛盾不能自动改时间线；冲突时 Canon 胜。
- **与最容易混淆概念的差异**：不是 Event。时间线是次序；事件是其上的节点。
- **一个小说生成例子**：Canon 已定「第一日拾玉、第二日试门」。草稿写成先试门再拾玉，时间线不改，Canon 胜。

### Foreshadowing / 伏笔

- **中文名**：伏笔
- **英文代码名**：Foreshadowing
- **一句话定义**：在先期场景中埋下、预期在后期回收的提示；本身不是自动生效的 Canon 变更。
- **生命周期/状态**：埋设 → 待回收 → 回收须再经场景生成、抽取候选变更与主编批准。
- **与最容易混淆概念的差异**：不是 Secret。伏笔是提示装置；秘密是知情上的隐瞒。
- **一个小说生成例子**：河滩泥里露出与祠门同形的缺口——这是伏笔；未批准前不能因此把「残玉是钥匙」写入 Canon。

### Validation Rule / 校验规则

- **中文名**：校验规则
- **英文代码名**：Validation Rule
- **一句话定义**：对照 Canon 与 Story Spec 检查候选变更能否提交人类裁决的规则。
- **生命周期/状态**：生效中（用于 Validate）。未通过者不能进入批准。规则本身不改 Canon。
- **与最容易混淆概念的差异**：不是 Approval。校验只决定能不能交给主编；批准才由主编作出。
- **一个小说生成例子**：规则检查「候选不得与『只有林晚能触活残玉』冲突」；冲突则不得进入批准。

### Violation / 违规

- **中文名**：违规
- **英文代码名**：Violation
- **一句话定义**：某条候选变更或草稿对照校验规则未通过的一次具体失败。
- **生命周期/状态**：检出 → 阻断进入批准 → 可开修复任务，或由主编拒绝相关候选。不得用自动批准消掉违规。
- **与最容易混淆概念的差异**：不是 Repair Task。违规是问题本身；修复任务是为消解该问题而开的工作。
- **一个小说生成例子**：候选「路人触活残玉」对照世界规则失败，记为一条违规，不能提交 Canon。

### Repair Task / 修复任务

- **中文名**：修复任务
- **英文代码名**：Repair Task
- **一句话定义**：为消解一次违规而指定的返工（改场景计划、重生成或重抽候选）；完成后仍须校验与人类裁决。
- **生命周期/状态**：开立 → 进行中 → 完成并再校验。修复完成不等于自动批准，更不等于自动改 Canon。
- **与最容易混淆概念的差异**：不是 Approval。修完只是再次进入抽取与校验；Canon 仍只在主编批准后提交。
- **一个小说生成例子**：因「路人触活」违规，重生成「河滩捡玉」并去掉路人触玉；新候选仍须主编批准。

### Approval / 批准

- **中文名**：批准
- **英文代码名**：Approval
- **一句话定义**：人类主编对通过校验的候选变更作出的肯定裁决；只有批准后的提交才会改 Canon。对应否定裁决为拒绝。
- **生命周期/状态**：待裁决 → 批准 / 拒绝。拒绝则不提交。不存在自动批准；模型与 bot 不得代批。
- **与最容易混淆概念的差异**：不是 Validate。校验是预检；批准是人类主编的裁决。
- **一个小说生成例子**：主编选择「批准」后，「残玉可开祠门」才提交进 Canon；系统不得自行批准。

### Revision / 修订版本

- **中文名**：修订版本
- **英文代码名**：Revision
- **一句话定义**：某一产物（规格、场景草稿、Canon 等）在一次改写后的新版本。
- **生命周期/状态**：当前版本 → 产生下一修订版本。Canon 的修订版本仍必须来自主编批准后的提交。
- **与最容易混淆概念的差异**：不是 Snapshot。修订版本是沿时间前进的新版；快照是某时刻的冻结副本。
- **一个小说生成例子**：场景草稿改掉「路人触玉」后成为修订版本 r2；r2 仍只产生候选变更，不直接改 Canon。

### Snapshot / 快照

- **中文名**：快照
- **英文代码名**：Snapshot
- **一句话定义**：在某一时刻冻结下来的只读副本（通常是当时的 Canon 或规格），用于回看，不代替当前 Canon。
- **生命周期/状态**：创建（冻结）→ 只读保留。回看快照不得绕过人类批准去改当前 Canon。
- **与最容易混淆概念的差异**：不是 Canon，也不是 Revision。快照是某刻副本；Canon 是当前已批准真相；修订版本是新的当前版。
- **一个小说生成例子**：试门场景开始前冻结一份 Canon 快照，供对照回看；草稿写乱也不能用快照或草稿覆盖当前 Canon。

## 3. 本节点明确不做

- 不启动 0.3，不写实现、接口、库表或代码。
- 不把自动批准、多项目写成 MVP 正常行为。
- 不新增、不删减本节以外的术语定义。
